## 用户偏好与工作方式

- 桌面界面和扩展需要紧凑、清晰，控件尽量 mini，减少解释性文字、重复信息、冗余图标和大块空白；长标题单行省略并可查看完整内容。
- 用户希望先实际观察、复现，再修改并验证；不要每改一点就打包，也不要把编译通过等同于用户场景已解决。清楚区分已观察事实和推测。
- 用户要求正常正式发布，不要擅自将产品或发布标成试用版；发布前仍应真实说明未验证的功能。
- 发布时核对源码提交、版本、标签、安装包、发布附件和 SHA-256 一致；检查安装器图标和实际运行效果。不要覆盖用户数据或清理现有工作目录。

## 常用命令

在项目目录运行 `npm run check:source`、`cargo test --manifest-path src-tauri/Cargo.toml`；Windows 安装包使用 `npm run bundle:win`。锁文件变化后若许可证清单检查提示过期，运行 `npm run licenses` 并检查生成文件。发布前确认真实下载与窗口行为，而不只运行自动测试。
